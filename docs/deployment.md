# Cloudflare deployment (production)

English | [中文](deployment.zh.md)

Operational runbook: bring production — `https://grillingsleek.online` — up behind Cloudflare and keep it healthy. The origin side runs on ttyo (`43.133.160.29`) via [`devops/ansible/deploy.yml`](../devops/ansible/deploy.yml); the why of the topology lives in the [GS-RFC](../.agents/gs-rfcs/implemented/2026-08-24-production-origin-via-host-gateway.md).

## Topology

```
Visitor ──HTTPS:443──> Cloudflare edge (proxied, Full strict) ──HTTPS:443──> host Caddy gateway (Origin CA) ──HTTP──> 127.0.0.1:8081 → container Caddy :8443 ──> Rust 127.0.0.1:8000 / static
```

| Layer  | Value                                                                                                                              |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| Edge   | 443, TLS terminated by Cloudflare; 443 is the only proxied HTTPS port with edge caching enabled                                    |
| Origin | host 443 → the VPS's systemd Caddy gateway (shared across services, `import /etc/caddy/conf.d/*.caddy`) holding the Origin CA cert |
| App    | container Caddy plain HTTP `:8443`, published loopback-only (`127.0.0.1:8081`)                                                     |

The gateway and the host firewall (default-deny inbound; 443 open to Cloudflare CIDRs only) already exist on ttyo — set up alongside the other service that shares the VPS. This runbook joins grilling-sleek to them.

## Prerequisites

- A Cloudflare account; the member creating certificates needs API access.
- `grillingsleek.online` at a registrar you control.
- SSH to `alice@ttyo`; a repo checkout (ansible inventory at the repo root).
- On ttyo: the host Caddy gateway running (`systemctl status caddy`) with `/etc/caddy/conf.d/` in place, and sudo for the gateway tasks (`--ask-become-pass`).

## 1. Onboard the zone (Cloudflare console)

1. Dashboard → **Onboard a domain** → enter `grillingsleek.online` → **Continue** → pick the plan.
2. Review the scanned DNS records; add missing ones under DNS → Records.
3. At the registrar, replace the nameservers with the two Cloudflare-assigned ones. If DNSSEC is active there, disable it before switching.
4. Wait for the zone status to become **Active**.

## 2. Point DNS at the origin (console)

1. DNS → Records → **Add record**: Type `A`, Name `@`, IPv4 address `43.133.160.29`, Proxy status **Proxied** (orange cloud), TTL Auto.
2. **Save**.

## 3. Issue the Origin CA certificate (console)

1. SSL/TLS → Origin Server → **Origin Certificates** → **Create Certificate**.
2. Keep the defaults: key generated by Cloudflare (RSA), hostnames `grillingsleek.online` + `*.grillingsleek.online`, PEM key format; choose the validity period.
3. Copy the **Origin Certificate** and **Private Key** — the key is shown only once.
4. Record the expiry date; Cloudflare sends no expiry notifications.

## 4. Install the certificate on ttyo

deploy.yml creates `~/docker/grilling-sleek/certs/` but never fetches the certificate. Place both files (out of band; key owner-readable only):

```
# on ttyo, as alice
install -m 0644 origin.pem ~/docker/grilling-sleek/certs/origin.pem
install -m 0600 origin.key ~/docker/grilling-sleek/certs/origin.key
```

The playbook copies them to `/etc/caddy/certs/grilling-sleek/` for the gateway ([site block template](../devops/ansible/templates/grilling-sleek.caddy.j2)) and reloads the gateway on change.

## 5. One-time edge setup (console)

1. **SSL mode** — SSL/TLS → Overview: **Full (strict)**, after the certificate from step 4 is on the host.
2. **Browser Cache TTL** — Caching → Configuration: **Respect Existing Headers**, so the origin's `max-age` reaches browsers as-is.
3. **Entry-HTML Cache Rule** — Rules → Overview → Create rule → Cache Rule: name `cache-entry-html`; When incoming requests match: `URI Path` `equals` `/`; Then → Cache eligibility → **Eligible for cache**; leave Edge TTL unset so the origin's `max-age=300` applies. Without this rule the entry HTML is always `DYNAMIC` — HTML never enters cache by default.
4. **Switch day only** (coming from the direct-8443 topology): delete the Origin Rule that rewrites the origin port to 8443 — Rules → Overview. The edge must connect on 443 before the deploy below flips the container to loopback-only.

## 6. Deploy and verify

1. Deploy from the repo root ([AGENTS.md §3](../AGENTS.md#3-commands)); the gateway tasks need root:

```
ansible-playbook devops/ansible/deploy.yml -e target=production --ask-become-pass
```

The playbook templates the site block, copies the certificate and reloads the gateway **before** recreating the container on `127.0.0.1:8081`. The image is pinned by `image_tag`; the deploy fails unless `/v1/healthz` reports `expected_version`.

2. Verify health and version: `curl -s https://grillingsleek.online/v1/healthz` → `version` equals the pinned tag in [`group_vars/production/vars.yml`](../devops/ansible/group_vars/production/vars.yml).
3. Verify edge caching (GET — HEAD is never cached): `curl -sD- -o /dev/null https://grillingsleek.online/ | grep -i cf-cache-status` → `MISS`, then `HIT` on repeat; `/assets/*` is cacheable by default (no rule needed).
4. Direct-to-origin probes from any non-Cloudflare network now fail by design: `curl -ksI --max-time 5 https://43.133.160.29/` times out (host firewall drops non-CF 443), and nothing listens on the old `:8443`.

## 7. Maintenance

- **Rotate the Origin CA certificate**: repeat steps 3–4, then re-run the deploy command — the changed copy reloads the gateway; the container is untouched.
- **Resync Cloudflare CIDRs**: when <https://www.cloudflare.com/ips/> changes, refresh the host firewall on ttyo (the sole enforcement point) and update `cloudflare_cidrs` in group_vars — the variable is the list's home in the docs.
- **Raise the version pin**: production deploys released tags only — a new version needs a release first.

When verification fails: `docker logs grilling-sleek` on ttyo for the app side, `journalctl -u caddy` for the gateway; recovery is fix-forward.
